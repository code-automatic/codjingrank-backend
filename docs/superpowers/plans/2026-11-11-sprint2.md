# Sprint 2 Implementation Plan

**Goal:** Integrate the approved fresh schema and catalog contract in task order.
**Spec:** `docs/DECISIONS.md`, `docs/FRONTEND_API_CONTRACT.md`, `docs/openapi.yaml`.
**Architecture:** Reuse net/http, pgx and the existing response envelope. New catalog DTOs use UUID strings; do not reinterpret legacy integer JWTs. Preserve Run/Submit/queue/judge behavior.

## Constraints and review focus

- Each feature uses a branch, with small commits; preserve unrelated local edits.
- Never bootstrap an existing database. Tests use a disposable project PostgreSQL16 database.
- Public catalog never exposes hidden tests or wrapper code. Active-account and level checks are enforced on the server.
- Package creation inserts exactly three levels atomically. Unlock requires every published problem in prior levels; empty levels do not block.
- Test malformed UUIDs, inactive accounts, empty pages, draft/archive exclusion, locked levels and immutable published judge inputs.
