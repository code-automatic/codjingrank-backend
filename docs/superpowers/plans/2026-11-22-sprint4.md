# Sprint 4 Backend Implementation Plan

> Use subagent-driven-development, with test-driven development for each API.

**Goal:** Deliver BE tasks 24–27 and 30, and the backend contract evidence for 32.
**Architecture:** PostgreSQL-backed AI reviews and separate Forum service, Gateway leaderboard.
**Tech Stack:** Go net/http, pgx, existing PostgreSQL and Redis.
**Spec:** ../specs/2026-11-18-sprint4-design.md and ../../openapi.yaml.

- [ ] AI (24–26): implement ai_service and its schema changes. Public read receives Bearer JWT at the service. Internal POST /internal/reviews/{id} receives a separate Bearer secret; submission worker sends it after successful Accepted finalization. Reconcile by judged_at cutoff. Prove eligibility, at-most-one row, failure isolation, retry and stale attempt behavior. Worker wiring is owned by the same implementer.
- [ ] Forum (30): implement forum_service with identical /api/v1 paths to OpenAPI; service validates JWT and active DB role. Test published visibility, nesting, like counters, tombstones and safe Markdown. Own Markdown dependency if required.
- [ ] Leaderboard (27): implement gateway package and register GET list and /me. Test guest rules, UTC boundaries, SQL ties and DTOs.
- [ ] Integration (32): Gateway proxies exact OpenAPI routes preserving JWT and strips identity headers, Docker/Compose/CI wiring, DB-backed acceptance, contract capture, implementation flags and handoff.

The work shares one sprint branch. Only the primary stages/commits changes, after checking GitNexus and reviewing the combined diff. Existing local state and workbook are excluded from staging. Use throwaway project PostgreSQL and provider doubles, no live provider calls. Verify full Go suite, vet/build, OpenAPI and service smoke before marking routes verified.
