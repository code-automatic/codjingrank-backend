# Sprint 3 Backend Implementation Plan

**Goal:** Deliver workbook BE tasks 16, 18, 19, 20 and 21, with reviewed merge-commit PRs and acceptance evidence.
**Architecture:** Preserve synchronous Run and PostgreSQL Pending → Redis LPUSH/BRPOP → worker → Piston. Reuse pgx, net/http, shared envelope and target schema; no new dependencies.
**Spec:** `docs/DECISIONS.md`, `docs/FRONTEND_API_CONTRACT.md`, `docs/openapi.yaml`, `schema.sql`.

## Constraints and interfaces

- Preserve unrelated local AGENTS/state/generated files. Each feature has its own branch and focused commits.
- Never execute user code on host or bootstrap an existing database. Test with dedicated PostgreSQL/Redis.
- Never expose hidden tests, wrappers, provider diagnostics or another learner's source.
- AI, leaderboard endpoints, FE17/22 and QA23 are outside this BE delivery.
- Worker claims use attempt fencing; only the current Running attempt may finalize. Recovery is bounded and periodic, with a finite retry budget.
- Accepted verdict, distinct source solution and progress writes share one transaction. Unlock stays dynamic.
- Root/v1 equivalent routes share payloads; history changes from `submissions` to `items/page/size/total`, latest absence changes404→200 null, stats removes rating. FE must adopt the already documented target contract.
